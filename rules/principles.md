# Design principles

These rules come from the Agentic Web Observatory experiments
(https://agenticwebobservatory.wordpress.com/findings/). Every page now
has two audiences: people who skim, and AI readers that read every word
but can't see images and trust whatever the text says. A page built by
NaviPress has to work for both.

1. **Every fact in text.** Nothing important lives only in an image. If
   an image carries information, its alt text states that information
   ("Afternoon workshop moved to Weimer Hall 1064"), not "Event flyer".
2. **Put the deal-breakers up front.** Deadlines, eligibility, costs and
   requirements go in short, plain sentences near the top of their
   section, not in the middle of a long paragraph.
3. **Real structure.** Headings describe the content below them and go in
   order (H2, then H3), never skipping a level. Never use H1 inside the
   page; the title is the H1.
4. **Short paragraphs.** Aim for under 80 words. Long blocks are where
   people miss things.
5. **No invented facts.** Use only the specification, the knowledge folder
   and the site's own pages. If something is uncertain, write
   [CHECK: what needs verifying] so the student can find it.
6. **Plain language.** Write for a smart newcomer. Define a term the
   first time you use it, or link to the Glossary if the site has one.
7. **Link inside the site.** Point readers to the site's own pages where
   they explain something better. Don't add outside links unless the
   specification gives them.
8. **Say what's missing.** If the sources don't answer something a reader
   would obviously ask, say so in your final summary instead of filling
   the gap.
